# クチズムあいうえお — Claude Code受け渡し一式

ひらがな復習アプリのMVPを実装するための、確定済み仕様と素材です。

## Claude Codeでの開始方法

1. このフォルダ全体をPCへ置く。
2. ターミナルでこのフォルダを開く。
3. `npm run validate` を実行し、素材検査が成功することを確認する。
4. Claude Codeを起動し、次のように依頼する。

> CLAUDE.md と MVP_SPEC.md を読み、素材を検査してから、ひらがな復習アプリのMVPを実装してください。仕様や確定素材を勝手に変更せず、不足や矛盾があれば実装前に報告してください。

## 内容

- `MVP_SPEC.md`: MVPの確定仕様
- `CLAUDE.md`: Claude Codeへの実装指示
- `js/hiragana-data.js`: 46文字の確定データ
- `assets/images/hiragana/`: 46文字の復習画像（WebP）
- `assets/images/ui/`: 画面背景（WebP）
- `assets/audio/`: 3つの確定効果音
- `docs/design-reference/`: スタート・結果画面のデザイン見本
- `scripts/validate-assets.mjs`: 素材の自動検査

読み上げ音声は固定音声ファイルではなく、MVPではブラウザのWeb Speech APIを使用します。

## 実装済みMVPの起動

Node.jsが使えるターミナルで、このフォルダを開き、次を実行してください。追加パッケージのインストールやビルドは不要です。

```powershell
npm start
```

ターミナルを開いたまま、ブラウザで http://127.0.0.1:4173/ を開いてください。HTMLファイルの直接ダブルクリックではなく、このURLを使います。終了するときはターミナルで Ctrl+C を押します。すでにサーバーが起動している場合は、URLを開くだけで確認できます。

## 手動確認

1. 「はじめる」を押すと「1もんめ / 20」とひらがな1文字が表示されることを確認します。
2. 「できた」「どうかな」「できなかった」を順に試します。それぞれ異なる効果音の後に、対応する復習画像と日本語のフレーズが出ることを確認します。効果音と読み上げが重ならないことも確認します。
3. 「できた」はフレーズ終了から約1秒後に進みます。「どうかな」「できなかった」はフレーズの後に「どうぞ」が入り、その終了から約2.5秒後に進みます。集計ではそれぞれ別の回答として記録されます。「はちのは」は「はちの」と末尾の「ハ」を別々に読み上げ、末尾が助詞の「わ」にならないようにしています。
4. 回答ボタンを連打しても、1問に複数回の回答が入らず、問題が飛ばないことを確認します。同じ回で文字が重複しないことを確認します。
5. 20問で結果画面になることを確認します。3つのボタンを順番に押し続けた場合、結果は「できた」7、「どうかな」7、「できなかった」6です。合計は20になります。
6. 「もういっかい」を押すと結果がリセットされ、新しく抽選された20問の1問目になることを確認します。前の回と同じ文字が一部出ることは正常です。
7. スマートフォン相当の横画面（例: 667×375、844×390）とタブレット相当（1024×768）で、ボタン・画像・結果数字が見切れず、スクロールなしで操作できることを確認します。PCでは F12 のデバイス表示切り替えで幅と高さを指定できます。
8. F12 の Console にエラーが出ていないことを確認します。音声が出ない場合は端末音量、サイトのミュート設定、日本語の読み上げ音声を確認します。読み上げを利用できない環境では警告を出し、画面操作は続けられます。

## ブラウザを起動しない自動検証

```powershell
npm run validate
npm test
```

素材検査では46文字のデータ・画像と背景・効果音の存在を照合します。テストでは実際のアプリコードを、DOM・音声・時計の代替環境で実行し、20問の完走、重複なしの抽選、回答ロック、素材の対応、音声の順序、読み上げ完了後の待ち時間、集計、再開始、音声が利用できない場合の継続、UTF-8を確認します。ブラウザや別プロセスを起動しません。

実際の音の聞こえ方、日本語音声の利用可否、画面の見た目、ブラウザコンソールは上記の手動確認が必要です。自動テストの成功だけでは、これらを確認済みとは扱いません。

読み上げは利用可能な日本語音声から、名前で識別できる女性声を優先します。該当する声がない場合は日本語の既定音声、次に先頭の日本語音声を使います。Web Speech APIには性別や明るさを直接指定する機能がないため、声質は端末の音声に依存します。pitchは1.1、rateは0.95（以前は0.85）に調整しています。

## GitHub Pages

ビルド不要の静的サイトです。`.nojekyll` を同梱し、リポジトリのルートをそのまま公開できます。画像・音声は既存素材を使用します。`npm start` はローカル確認専用で、PagesではNode.jsサーバーを動かしません。

### 公開する際の手順（今回はpushしません）

1. `npm run validate` と `npm test` が成功することを確認します。
2. GitHubで空のリポジトリを作成します。無料プランでは公開リポジトリを使用します。
3. Gitが未初期化の場合は `git init -b main`、`git add .`、`git commit -m "Initial MVP"` を実行します。初期コミット済みの場合は不要です。Gitが利用できない環境では、先にGit for Windowsをインストールします。
4. 公開してよい段階になったら、`git remote add origin https://github.com/OWNER/REPOSITORY.git` と `git push -u origin main` を実行します。`OWNER` と `REPOSITORY` は自分の値に置き換えます。この準備作業ではpushしません。
5. リポジトリの **Settings → Pages → Build and deployment** を開き、**Source: Deploy from a branch**、**Branch: main**、**Folder: /(root)** を選んで **Save** します。`docs` はデザイン見本用なので公開元に選びません。
6. 公開処理が完了したら、Pagesに表示されるURL（通常 `https://OWNER.github.io/REPOSITORY/`）を開き、上記の手動確認を行います。デプロイ状況は **Actions** で確認できます。

設定手順は [GitHub公式ドキュメント](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) に基づきます。

### 相対パスと公開対象

HTML・CSS・JavaScriptの読み込み、背景、46文字の画像、3効果音は相対パスです。`npm test` では `/kuchism-aiueo-mvp/` のようなサブディレクトリから参照を解決し、すべての実行用ファイルが存在することと、ファイル名の大文字・小文字が一致することを確認します。ブラウザは起動しません。

`.gitignore` で `.browser-check`、`browser-check`、一時ファイル、ログ、テスト出力、ローカル設定などをGitの追加対象から除外します。Pagesへの除外は、これらをコミットしないことで実現します。すでに追跡済みのファイルは `.gitignore` だけでは除外できないため、初回push前に `git ls-files` で不要なファイルが入っていないことを確認します。実行に必要な公開ファイルは `index.html`、`css/`、`js/`、`assets/`、`.nojekyll` です。
